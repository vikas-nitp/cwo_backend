# CardOptimal Backend

FastAPI service that serves validated domestic-flight card offers. No database required — all data is file-based JSON/CSV.

---

## Setup

```bash
pip install -r requirements-dev.txt
```

---

## Running

```bash
uvicorn app.main:app --reload --port 8001
```

API docs available at `http://localhost:8001/docs`.

---

## Data pipeline

Run these whenever cardsage produces new output or offer data changes.

**Step 1 — Convert cardsage scrape output to CSV**

```bash
# From WORKSPACE root (auto-picks latest combined output date)
python3 cwo_backend/scripts/cardsage_to_snapshot.py

# Or pin a specific date
CARDSAGE_COMBINED_DIR=cardsage/output/combined/2026-09-21 \
  python3 cwo_backend/scripts/cardsage_to_snapshot.py
```

Writes `data/source/offers.csv` (gitignored — pipeline output).  
Falls back to `data/source/demo_offers.csv` automatically when no scraped data is present.

**Step 2 — Rebuild distribution bundle**

```bash
# From cwo_backend/
python3 scripts/build_data_bundle.py
```

Reads `data/source/offers.csv` (or demo fallback) → writes `data/generated/` and `data/distribution/frontend/`.

**Step 3 — Sync to frontend**

```bash
# From cardwiseoffer/
npm run data:sync-backend
```

Copies `data/generated/` snapshots into the frontend's `src/data/generated/`.

## Feature flags

`app/core/feature_flags.py` (`FeatureFlags` Pydantic model) is the **single source of truth**. All other flag files are derived from it.

```bash
# Add or update a flag — edits feature_flags.py then regenerates derived files
python3 scripts/add_feature_flag.py <flagName> <true|false>

# Example
python3 scripts/add_feature_flag.py couponCodeEnabled true
```

**Derived files** (never edit by hand — regenerated by `sync_feature_flags.py`):

| File | What it is |
|---|---|
| `cardwiseoffer/src/config/featureCapabilities.ts` | TS capability key → flag mapping |
| `cardwiseoffer/src/data/generated/featureFlags.json` | Runtime flag values for the frontend bundle |

To regenerate derived files without adding a flag (e.g. after a manual edit to `feature_flags.py`):

```bash
python3 scripts/sync_feature_flags.py
```

**Runtime overrides** (`data/config/feature_flags.json`): values here override the Pydantic defaults at startup. Keep only flags whose runtime value differs from the model default. `load_feature_flags()` falls back to `FeatureFlags()` defaults when the file is absent.

Active flags of note:

| Flag | Default | Effect |
|---|---|---|
| `tieredDiscountEnabled` | `true` | Uses `discount_tiers` table in `estimate_savings()` for tier-accurate savings instead of scalar formula |
| `bookingAmountComparisonEnabled` | `false` (default) / `true` (override) | Allows `booking_amount` in search requests |
| `couponCodeEnabled` | `false` | Exposes coupon codes in search response |

**Fare validation** (`/api/v1/search`): `booking_amount` must be a whole number ≥ ₹1,000 (no paise, no sub-₹1k values). Enforced in `app/schemas/search.py`.

## Domain models

| Model | File | Notes |
|---|---|---|
| `Offer` | `app/domain/models.py` | Core offer record; `discount_tiers: list[DiscountTier] \| None` holds the full tier table for tiered EMI offers |
| `DiscountTier` | `app/domain/models.py` | One spend-range row: `min_amount`, `max_amount` (None = open), `discount_type`, `discount_value`, `max_discount` |
| `SavingsEstimate` | `app/domain/calculations.py` | Result of `estimate_savings(offer, booking_amount, tiered_discount_enabled=…)` |

---

## Routes

| File | Prefix | Purpose |
|------|--------|---------|
| `health.py` | `/health` | Liveness probe |
| `meta.py` | `/api/v1` | Dataset metadata and last-updated timestamp |
| `offers.py` | `/api/v1/offers` | Paginated offer catalogue |
| `search.py` | `/api/v1/search` | Offer search by route, date, bank |
| `feature_flags.py` | `/api/v1/feature-flags` | Feature flag values |
| `availability.py` | `/api/v1/availability` | Data availability window |
| `user_cards.py` | `/api/v1/user/cards` | Saved cards (in-memory, per session) |
| `subscriptions.py` | `/api/v1/subscriptions` | Email capture for offer alerts |
| `visitors.py` | `/api/v1/visitors/count` | Active session count (2-min TTL) |

## Data source layout

```
data/
├── source/
│   ├── offers.csv          ← pipeline output (gitignored; regenerated by cardsage_to_snapshot.py)
│   └── demo_offers.csv     ← hand-curated fallback (committed; used when offers.csv is absent)
├── generated/              ← built by build_data_bundle.py (committed)
│   ├── offers.snapshot.json
│   ├── metadata.snapshot.json
│   ├── facets.snapshot.json
│   └── manifest.json
├── distribution/
│   └── frontend/           ← built by build_data_bundle.py (committed)
│       ├── offers.json
│       ├── metadata.json
│       ├── airports.json
│       └── featureFlags.json
└── config/
    └── feature_flags.json  ← canonical flag values (committed)
```
